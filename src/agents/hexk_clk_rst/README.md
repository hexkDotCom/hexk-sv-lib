# hexk_clk_rst

Clock and reset agent: one clock and one reset of a testbench,
generated by the interface `hexk_clk_rst_if`, changed from sequences and watched by a
monitor. The contract is `docs/api/hexk_clk_rst.md`.

| File | Content |
|---|---|
| `hexk_clk_rst.f` | filelist; compile it after `src/uvm/hexk_uvm.f` |
| `hexk_clk_rst.core` | FuseSoC core `hexkdotcom:hexk:clk_rst` |
| `hexk_clk_rst_if.sv` | the interface: clock generator, reset pin, clock count |
| `hexk_clk_rst_pkg.sv` | the package, with the type `hexk_clk_rst_op_e` |
| `hexk_clk_rst_item.sv` | the item of the driver and of the monitor |
| `hexk_clk_rst_agent_cfg.sv` | the cfg: interface, mode, clock and reset settings |
| `hexk_clk_rst_status.sv` | what changes during the run: reset events, `in_reset`, the clock being driven |
| `hexk_clk_rst_driver.sv`, `hexk_clk_rst_monitor.sv`, `hexk_clk_rst_agent.sv` | the agent |
| `sequences/` | reset, frequency, stop and start sequences |

Usage in short: instantiate `hexk_clk_rst_if` in the testbench top and connect `clk` and
`rst` to the DUT; create a `hexk_clk_rst_agent_cfg`, assign `vif`, and hand it to a
`hexk_clk_rst_agent` before its build phase: assign it, or, from a parent that cannot see
the type of the agent, set it in `uvm_config_db`;
start `hexk_clk_rst_reset_seq` on `agent.sqr` in the reset phase of the test.

Known limits: periods are whole picoseconds; Verilator 5.046 simulates one instance of the
interface correctly and not several (see the contract, section 4).
